# Parallel work: how the agents coordinate

Several agents work on oxruby at once, each in its own git worktree and
branch. This file is the contract between them. Read it in full before you
start, together with `AGENTS.md`, `docs/ROADMAP.md` (oxcop) and
`docs/OXTREE.md` (oxtree).

## Setup

- Your worktree is `.worktrees/<name>`. Your branch has the same name and
  starts from `main`. All worktrees share one repository, so every branch
  is visible to every agent: `git log other-agent`, `git show`.
- `main` is not checked out anywhere, and you never check it out. It only
  moves through `script/land`.
- References, read-only, under `/Users/teddy/_startup/rubocop-rs/`:
  `rubocop` (RuboCop 1.91.0), `rubocop-rails` (2.37.0), `rubocop-rspec`
  (3.10.2), `syntax_tree`, `syntax_tree-erb`, and `code`,
  the user's app and the real-world test corpus. Docs say `../rubocop`
  relative to the main checkout. From a worktree that is
  `../../../rubocop`, so use the absolute paths. Never write to any of them, and never run `bundle install`,
  `npm ci` or anything else that changes them.

## Landing work on main: `script/land`

Land early and often: whenever one or more cops or a coherent piece of
infrastructure is green. A small landing is easy for everyone to rebase
onto; a three-hour branch is not.

1. Commit on your branch, using the commit trailers from your instructions.
2. Run `script/land`. It:
   - rebases your branch onto `main`. If that conflicts, it aborts the
     rebase; run `git rebase main` yourself, resolve, then land again;
   - checks fmt, clippy, tests and that every crate root has
     `#![forbid(unsafe_code)]`. When only cop files changed, it runs just
     those cops' upstream specs. When anything shared changed (mixins,
     `ast/`, config, the shim, Cargo files), it runs every ported spec plus
     `script/compare_with_rubocop ../code`, which must report 0 mismatched
     files;
   - takes the landing lock first (`.git/land.lock`, shared by all
     worktrees), so landings run one at a time and a slow full gate can't be
     starved by faster cop landings. Expect to wait a few minutes behind
     someone else's full gate. A lock left by a killed landing is broken
     automatically;
   - moves `main` with `git update-ref refs/heads/main HEAD <old>`. If main
     moved anyway the swap fails, and it rebases and retries.
3. Never move `main` any other way: no `git push . HEAD:main`, no
   `git branch -f main`, no `--no-verify` equivalents. Never force-update
   it. Never push to GitHub.

`script/land --dry-run` runs the gates without landing. `FULL=1` forces the
full gates. If the full gate fails for a reason that is clearly someone
else's (main itself is red), say so in your notes, don't land on top of it,
keep working, and try again later.

## Ownership

Each agent owns the paths listed for it. Outside them:

- **Cop files** (`crates/oxcop/src/cop/<dept>/<cop>.rs`): only the agent
  whose range includes that cop creates it. The registry is generated by
  `build.rs`, so a new cop touches no shared file. Only land a cop once its
  whole upstream spec file passes, and passes by actually calling the
  binary; landing it is what turns its spec on for everyone.
- **New shared helpers** (a new `cop/mixin/*.rs`, `cop/correctors/*.rs`,
  `cop/variable_force/`, a new module under `ast/`): claim one before
  writing it, so two agents don't port the same mixin:

  ```sh
  mkdir /Users/teddy/_startup/rubocop-rs/oxruby/.coord/claims/<file-stem> \
    && echo "<your name>" > /Users/teddy/_startup/rubocop-rs/oxruby/.coord/claims/<file-stem>/owner
  ```

  `mkdir` is atomic. If it fails, someone else owns it: `cat` the owner,
  check `git log main -- <path>` and `git log <owner> -- <path>`, and port
  other cops meanwhile. If you need it now, cherry-pick the owner's commit
  rather than rewriting it. Owners land a claimed helper with the first cop
  that uses it, as soon as possible. The stem is the file name, e.g.
  `alignment`, `surrounding_space`, `percent_literal`, `heredoc`.
- **Existing shared files** (`ast/node.rs`, `ast/node_pattern.rs`,
  `cop/base.rs`, existing mixins and so on): small, additive edits are
  fine. Add a method or a case, don't reorganize. Land them soon so the
  conflict window stays short. If a change would be large or would change
  behaviour others rely on, ask the owner through your notes file, or do it
  in its own landing with the full gate.
- **Docs:** write your progress in `docs/agents/<name>.md`, which only you
  edit. Only the coordinator edits `docs/ROADMAP.md`, `docs/OXTREE.md`,
  `docs/PARALLEL.md`, `README.md` and `AGENTS.md`. When a spec can't pass
  for a principled reason, record it in your notes file and the
  coordinator will fold it into the roadmap.
- **Root `Cargo.toml` / `Cargo.lock`:** declare dependencies in your own
  crate's `Cargo.toml`. Only touch the root when you must, keep the edit
  minimal, and never change the `ruby-prism` pin (`=2.0.0-rc.2`) or the oxc
  patch.

## Roster

Round 3 (2026-10-21): plugin cops. Rounds 1 and 2 finished; their notes are
in `docs/agents/` and their rosters are in git history. The scope is the
plugin cops `../code` enables, not whole plugins.

| Name | Owns | Goal, in order |
| --- | --- | --- |
| `rails` | `crates/oxcop/src/cop/rails/**` (cops, and any Rails-only helpers in a `rails/<helper>/mod.rs` subdirectory) | Rails/TimeZoneAssignment, Rails/TimeZone, Rails/HttpStatusNameConsistency, each with its whole vendored spec green. |
| `rspec` | `crates/oxcop/src/cop/rspec/**` (cops, plus rubocop-rspec's base and mixins such as `RSpec::Language`, `EmptyLineSeparation`, `FinalEndLocation` in `rspec/<helper>/mod.rs` subdirectories) | RSpec/EmptyLineAfterHook and RSpec/EmptyLineAfterExample, each with its whole vendored spec green, smoke tests included. |

How plugin cops work (landed before this round):

- Specs: `rake vendor:plugins` copies `spec/rubocop/cop/rails/` and
  `spec/rubocop/cop/rspec/`, the support those specs use
  (`spec/support/rubocop-rails/`, `spec/support/rubocop-rspec/`), and
  rubocop-rspec's `spec/smoke_tests/`. All vendored: never edit them.
  `spec/oxcop/plugins.rb` gives each plugin's specs a default configuration
  with only that plugin integrated, plus rubocop-rspec's spec_helper setup.
- Registry: a cop in `cop/rails/` or `cop/rspec/` only runs once its plugin
  is loaded (`Config::cop_registered`, `cop::base::PLUGIN_DEPARTMENTS`): from
  `plugins:`/`require:` in a real run, or when a `--raw-config` has the
  `Rails`/`RSpec` department key, as the specs' dumped config does.
- `script/land` treats `cop/rails/*.rs` and `cop/rspec/*.rs` as cop files.
  A helper subdirectory (`cop/rspec/language/mod.rs`) counts as shared and
  takes the full gate. That's fine: land it with the first cop that uses it.
- `../code` has no offenses for these five cops today, so the compare only
  proves no false positives. The specs prove detection.

The `cop/mixin/` files that already exist are listed in `ROADMAP.md`. The
mixins most needed but not yet ported are Alignment, SurroundingSpace,
PercentLiteral, Heredoc, CheckAssignment, StatementModifier,
EndKeywordAlignment, TrailingComma, and the multiline and first-element
families. Claim one before porting it.

## Shared machine

Up to 13 agents share one 14-core, 26 GB machine.

- Build only your crate: `cargo build -p oxcop` or `-p oxtree`.
- Use debug builds unless you are timing something.
- Don't run builds or specs in a loop, and don't leave background processes
  running when you finish.
- Run single spec files while iterating. The full gate runs at landing.

## Finishing

You will run out of context long before you run out of cops. That's
expected. When your context is getting long, or your scope is done:

1. Land what's green.
2. Update `docs/agents/<name>.md`: what's done, what's left, blockers,
   principled spec failures, decisions for the user. Land that too.
3. Make sure nothing uncommitted is left. Put work in progress on a local branch,
   `<name>-wip`. Never push it to GitHub.
4. Write a final report.

A fresh agent will continue from your notes file.
